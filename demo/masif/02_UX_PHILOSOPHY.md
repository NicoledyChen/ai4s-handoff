# 用户体验与哲学架构：让科学家抓住真正需要判断的地方

版本：概念设计 v0.1 · 2026-09-10

配图：[Agent 框架 PNG](diagrams/02-agent-framework.png) · [可编辑 SVG](diagrams/02-agent-framework.svg)。它说明任务、角色与多级信息如何协同，不是模拟研究组。

本文将团队已通过 AI 实跑得到的 MaSIF 探索成果转为面向投资人的产品化方案，承接[基础设施架构](01_INFRA_ARCHITECTURE.md)，与[MaSIF 演示案例](03_MASIF_DEMO_CASE.md)配套。主线是：已有成果 → Skill 化 → 稳定工作流，以及角色、群聊与多级结果展示。

## 1. 产品主张：机械工作可委派，科学判断有抓手

设计能够结合目标蛋白的 binder，需要经过结构分析、设计、筛选与预测复核。问题不仅是计算步骤多，还在于一个选择会改变后续工作，而依据散落在结构文件、脚本、图表和讨论里。

用户已确认：Word 指南中的科学流程与数值来自团队使用 AI 实际运行的探索成果。产品化要把这条已有轨迹中的有效步骤、决策依据和交接方式沉淀为 Skill 等可复用规程，让后续工作能够稳定跑出接近的探索轨迹。

这个 app 延续原始 Lumen 的“同一结果，多级展开”：科学家用角色与群聊表达意图，在结果工作面比较方案，沿证据入口回到原始工具。产品要减少搬运上下文、整理输出和协调依赖的负担，把注意力留给“设计哪里、允许改什么、保留哪些结构假设、冲突后怎么办”。下一步验证产品化流程的稳定性与协作收益。

稳定不是逐字一致，而是输入、决策、产物、验证、恢复合同稳定：输入版本可定位，关键选择与预算有记录，产物及谱系可检查，验证条件明确，失败或中断后能够接续。允许随机采样与表达不同，但不能悄悄改变目标、越过决策边界或丢掉证据。

任务先于角色。分析、可视化和流程执行各有输入、产物、验证与交接约定，依托已有文件、Notebook、Git、结构工具和计算平台。工作不应只留在某个助手的聊天记忆里；更换模型、退出界面之后，团队仍应能找到并继续使用产物。

## 2. 角色不是模拟研究组，而是可寻址的工作入口

**分析角色**回答“这些候选为什么值得保留、证据哪里冲突”，维护比较、方法、限制与来源。**可视化角色**回答“怎样看清结构与差异”，维护表面着色、结构叠合、来源分组及图形变换。**流程角色**回答“当前卡在哪里、什么已获批准、下一步会影响什么”，维护依赖、预算范围、决策卡和接续状态。

不为 MaSIF、Rosetta、MotifGraft、AF3 各造一个人格；它们是任务可调用的工具，不是产品的组织结构。同一角色可由不同执行实例承接，角色名称也不授予权限。角色卡显示“负责的任务／结果对象”，详情另列实际执行者、运行实例与授权范围。

群聊是这些工作关系的人机交互界面：人可以点名追问，角色围绕同一对象交接或保留分歧。后台每次调用不必变成发言，群里主要出现关键变化、待决问题和交付。多角色意见一致不等于独立科学验证，聊天里的“收到”也不等于任务完成。

## 3. 可直接画草图的同一工作场景

顶部固定显示项目目标、当前节点和输入版本，不反复铺设“合成／回放”标签。左侧为窄幅角色与群聊区；中央是主要结果工作面，容纳结构、比较与当前决策卡；右侧证据抽屉按需展开，说明内容来源及执行方式。聊天消息和结构选区引用同一结果对象及版本，切换入口不复制另一份结论。

中央从上到下依次是“结果标题与状态”“最重要发现与限制”“结构或候选比较”“推荐、备选与待确认动作”。决策卡可展开当前参数、观察依据、预期候选范围、资源影响、风险和选择理由；没有依据的预估显示“待估算”。证据抽屉提供输入、变换、来源、版本、复核及原生文件入口，未知项不可补写成完整日志。

主按钮用“确认此位点”“确认设计边界”“保存母体选择”“批准复核范围”等具体动词。邻近入口用“展开依据”“比较备选”“查看原始文件”。PULL 是展开信息，APPROVE 才是对明确动作与范围的授权；打开证据、点选候选和群聊共识均不自动扩权。

## 4. 四个关口：人决定什么，系统承接什么

以下职责用于把已有实跑链路固化为稳定工作流。Skill 化对应 N1／4“位点意图确认”、N2／8“设计边界约束”、N3／11“母体去冗余与选择”、N4／12“冲突复核”，分别封装输入检查、执行步骤、产物检查与暂停条件。它们是可复用工作规程，不是新增四个人格；四关口是展示切片，不取消指南中其他必要确认。

### N1／阶段 4：位点意图确认

人确认进入搜索的表面位点、是否指定目标残基，以及可接受的位点偏移。系统可整理表面特征、位点重叠、目标残基覆盖和搜索范围，不把位点编号当成质量等级。分析角色说明生物学意图与几何覆盖是否一致，可视化角色并列显示限制前后的表面，流程角色记录选择并检查输入歧义。

关键文案：“高分表面不自动等于目标表位。请确认要设计的区域。”未知的功能目的保留为待确认；不能通过默认按钮替科学家发明一个目的。[依据：指南第四环节](sources/guide-extracted.txt)

### N2／阶段 8：Rosetta 可改／不可改边界

人确认 target 与 binder 的链角色、可设计残基、固定 motif、骨架柔性、允许氨基酸集合和采样预算。系统可检查链与残基映射，生成配置，并在已确认范围内整理松弛前后比较。分析角色解释自由度带来的取舍，可视化角色区分固定、可设计与可移动区域，流程角色明确哪些边界变化需要再次确认。

关键文案：“固定序列不等于固定骨架；请分别确认。”不把指南实例中的配置冒充通用默认，也不把“能量改善”压缩为“设计成功”。[依据：指南第八环节](sources/guide-extracted.txt)

### N3／阶段 11：兼顾来源多样性的母体选择

人确认母体数量、seed 或 scaffold 来源配额，以及优先保留的结构模式。系统可汇总硬约束、指标取舍、来源构成与聚类，提出多样化集合和更严格的备选集合。分析角色解释为何不只按总分取前列，可视化角色呈现来源与界面模式，流程角色记录配额和选择理由。

关键文案：“候选很多，不代表独立结构假设很多。”指南中的聚合数量是团队实跑成果的文档记录；来源详情应保留其出处与计算口径，不写成当前前端刚运行所得。MotifGraft 可扩增候选，流程图不能画成一路递减的漏斗。[依据：指南第十一环节](sources/guide-extracted.txt)

### N4／阶段 12：AF3 冲突与复核决策

人决定哪些候选进入更深入复核、采用什么重复范围与预算，以及位点一致性要求。系统可并列整理结构叠合、界面置信度、binder 折叠和不同 model seeds 的一致性。分析角色保留相互冲突的证据，可视化角色突出偏移与翻转，流程角色在冲突处提出追加复核、降级候选或返回母体选择的明确分支。

关键文案：“预测置信度与位点一致性冲突；不能只取最高分。”终点是“计算复核／待进一步验证”，不是实验成功。[依据：指南第十二环节](sources/guide-extracted.txt)

## 5. 同一结果的五级信息，不是五份越来越短的答案

以新增交互脚本 `DEMO-M01` 的 AF3 冲突卡为例，说明五级信息如何工作。`DEMO-M01` 至 `DEMO-M04` 及个别冲突对话是我们为串接产品体验新增的脚本，不是团队真实候选的映射或抽样；原始结构文件当前未提供。脚本与处置统一见 [演示数据骨架](demo-fixtures.json)，其身份在来源详情说明，不据此否定指南中的实跑成果。

- **Signal：**“需要决定：位点一致性需复核。”短卡突出待决问题和关键限制，来源可一键展开，不层层重复贴标。
- **Summary：**“预测信号存在分歧，当前不能据此入选；可追加复核或返回母体选择。”这是脚本中的产品文案，不把建议写成结论。
- **Workbench：**展示结构比较与来源切换的交互，选定待复核集合；选择本身不提交任务，结构示意也不充当真实候选的几何证据。
- **Analysis：**解释设计位点一致性、界面指标与重复一致性如何影响判断，展示反证及缺失证据，不宣称还原模型私有推理。
- **Source：**分别定位团队实跑成果的指南段落、新增交互脚本、对象版本与当前执行方式；尚未收到的原始结构和运行记录写“未提供”，不推断它们不存在。

三个角色各自维护所负责对象的分层表达，而非交给一个全局摘要员。拟议展示校验检查对象版本、受众、来源、状态、重要限制与下钻是否保留；语义正确性仍需复核。临时隐藏一个候选只改变视图，从分析中排除它则是方法变更，应形成新版本并检查下游影响。

## 6. 三分钟演示节奏与诚实边界

开场约二十秒，给出团队已有实跑轨迹与本次产品化目标。随后约两分钟沿 N1–N4 各停留一次：圈定位点、看清可改边界、按来源选母体、在冲突处暂停。最后四十秒点名分析角色，展开同一张结果卡到来源，再展示决定如何成为可保存的接续记录。重点是已有探索怎样沉淀成可复用工作，以及人的判断如何改变它，不是角色轮流发言。

来源与执行说明放在按需详情：`sourceKind=document-example/offline-result/synthetic` 描述内容来源，`executionMode=replay/local-interaction/live` 描述本次执行方式。这里 `document-example` 指文档中记载的团队实跑成果，不表示科研虚构；`synthetic` 仅用于新增脚本等人工构造内容；导入原始离线结果后再按实际情况标记。科学结果曾真实运行，与当前界面是否实时调用后端，是两个问题。

当前 HTML 展示层尚未接入计算后台；Grok 风格群聊和 Harness 是拟议复用方向，其接入、调度、权限与追溯边界仍需验证。这一产品接入状态不否定团队已经取得的 AI 实跑成果。主画面保持干净，重要科学限制仍直接可见，来源与执行详情始终可打开；不把本地交互说成实时计算，也不提前承诺产品化后的速度、成本或成功率。
